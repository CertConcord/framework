# Applications sharing the core — draft 03

| Track                                 | Application-specific scope                                                                                        | Relationship to the core                                                                                             | Current maturity                                                                                                                               |
| ------------------------------------- | ----------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| Document trust                        | Personal and organizational signing/seals, document encryption, required time and historical evidence             | First complete specification baseline                                                                                | Draft with executable candidate flows and documented gaps                                                                                      |
| S/MIME                                | Email address qualification, message encryption/signing, recipient and MIME processing, mail-client compatibility | Reuses the shared certificate/full-CRL/authority engine with explicit mailbox and operation-purpose binding          | [Selected S/MIME application](../docs/smime-application.md); opaque P-256 signing and RSA-OAEP/AES-GCM encryption with bounded MIME processing |
| Standalone trusted timestamp services | TSA admission, clock assurance, requests/responses, status and durable recovery                                   | Reuses authority admission, certified service keys, lifecycle and evidence semantics; adds timestamp-specific duties | [Selected RFC 3161 application](../docs/timestamp-application.md); bounded direct-root/full-CRL profile with explicit clock policy             |
| Organizational delegation             | One attenuating grant path, a fixed workload, independent person approvals and durable CMS execution              | Reuses organization-seal credentials, ordinary WebAuthn, COMMON controls and the existing execution gateway          | [Selected current-state application](../docs/organization-delegation.md); bounded hierarchical grants with original approval evidence          |
| Further certificate applications      | Their explicitly selected purposes, operations and relying-party rules                                            | Must use an identified shared-core revision and an explicit extension contract                                       | Proposed individually                                                                                                                          |

Independent progress means separate application milestones, not unrelated standards. Changes to a shared credential or lifecycle rule require impact analysis for every adopted application. An implementation need only claim the applications and profiles it actually implements.
