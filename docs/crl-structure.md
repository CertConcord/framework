# Complete CRL outer-structure admission

The direct full-CRL verifier admits the `CertificateList` structure defined by [RFC 5280 sections 5.1 and 5.1.1](https://www.rfc-editor.org/rfc/rfc5280.html#section-5.1): one DER SEQUENCE with exactly three fields, `tbsCertList`, `signatureAlgorithm` and `signatureValue`. Its signature authenticates the encoded `TBSCertList`; preserving that signed region does not make a different outer container or an additional outer field admissible.

After DER framing succeeds, `verifyCRL` checks the outer tag and field count before reading the signature or status fields. A structural mismatch returns the frozen typed result `status: INVALID`, `overall: INVALID`, `reason: CRL_STRUCTURE`, without a CRL number, publication interval or complete-issuer scope. DER framing errors retain their existing codes. A correctly shaped object still has to pass signature, issuer, time, extension, rollback and revocation checks. In particular, a signed-TBS alteration remains `CRL_SIGNATURE`; a valid revoked result remains `REVOKED`, not a structural failure.

The external-identity adapter accepts only authenticated complete-issuer status before updating its journal. A malformed wrapper must not create or change the number, exact-byte digest or revision. This holds both before and after a canonical CRL is admitted, across a journal reopen, and when the malformed object carries a higher number. A later canonical CRL must remain usable. A distinct, correctly signed CRL with the same number still triggers `IDENTITY_CRL_FORK`; structural rejection does not disable that protection.

[crl-structure.json](../reference/vectors/crl-structure.json) contains 13 frozen synthetic DER inputs and SHA-256 commitments: four correctly signed status controls, eight outer-structure variants, and one three-field signed-TBS alteration. The [generator](../tools/create-crl-structure-vectors.mjs) assembles CRL DER independently and signs it with Node's ECDSA primitive. It does not call the reference CRL producer or parser. Issuer and subject certificates use the existing certificate fixture builder; fresh private keys stay in memory. Regeneration writes a new output path and produces new synthetic keys and signatures rather than silently replacing the frozen corpus.

The [regressions](../reference/crl-structure.test.mjs) independently measure the original TLV boundaries and retained bytes, verify complete embedded signatures with Node crypto, and reject changed keys and signatures. Inputs missing an outer field have no complete embedded signature; their signed ancestor is a separate control. OpenSSL parses and verifies the exact frozen bytes, rejecting malformed containers and the signed-number alteration while accepting the four correctly signed controls. Its signature result does not itself decide a particular certificate's revocation status.

These tests cover direct full-CRL structure and bounded identity-journal admission. They do not establish production issuer trust, a deployed revocation bypass or PAdES behavior. The existing issuer-certificate admission, cRLSign usage and relying-party trust configuration remain required. No hardware qualification or stable conformance claim follows from these synthetic vectors.
