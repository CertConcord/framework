# WebAuthn authenticator extension outputs

[WebAuthn Level 3 section 5.7.4](https://www.w3.org/TR/2026/REC-webauthn-3-20260825/#sctn-authenticator-extension-outputs) defines authenticator extension outputs as a CBOR map with text-string keys. This structure is distinct from client extension results.

When the ED flag is set, both reference registration and assertion verification require exactly one extension-output map. Every top-level key must be a text string. Integer identifiers, mixed text/integer identifiers, arrays, byte strings, scalars and tagged wrappers fail with `AUTHENTICATOR_EXTENSIONS` when they reach this shape check. The bounded CBOR decoder rejects unsupported key types, duplicate keys, truncated encodings and trailing data separately. Registration still requires the credential public key before the extension map; the extension map cannot substitute for the COSE key. With ED clear, no extension payload is allowed.

An empty map and unknown text identifiers remain admissible at this structural layer. Values retain the bounded codec's existing supported forms; nested integer keys inside an extension value are not top-level extension identifiers. This check neither interprets unknown extensions nor grants their values authority. An extension that affects an application's policy still needs its own semantics and processing contract.

The shared check preserves ceremony type, challenge, origin, RP ID, credential binding, presence and verification flags, signature verification, backup eligibility and counter validation. `none` attestation and packed self attestation remain unverified as authenticator identities, with assurance `UNASSESSED`. Passing this check does not authorize a document signature or establish hardware, account or production qualification.

[Frozen raw vectors](../reference/vectors/webauthn-authenticator-extensions.json) contain fresh synthetic P-256 assertions, `none` registrations and packed self attestations. The [generator](../tools/create-webauthn-extension-vectors.mjs) uses an independent CBOR writer and never serializes private keys. The [tests](../reference/webauthn-extensions.test.mjs) verify the raw signature input using Node's cryptographic primitives, exercise both public verification functions, and preserve negative signature, context, credential, flag and counter controls. Malformed extension structures in signed assertions and self attestations have mathematically valid signatures, so their rejection establishes structural admission rather than signature failure.
