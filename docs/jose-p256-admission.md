# JOSE P-256 admission

The draft JOSE implementation admits `ES256` only with a P-256 key, SHA-256 and a 64-byte `R || S` signature, as specified by [RFC 7518 section 3.4](https://www.rfc-editor.org/rfc/rfc7518.html#section-3.4). A valid ECDSA signature made with another curve does not satisfy this algorithm contract. The same curve selection applies to private signing keys, directly supplied public keys and certificate public keys. Missing or unsupported protected algorithms are rejected before signature verification; a caller's allow-list cannot override the key requirement. Other selected JOSE algorithms retain their existing contracts.

P-256 JWK coordinates use canonical base64url and exactly 32 bytes for each of `x` and `y`, including any leading zero octets. [RFC 7518 sections 6.2.1.2–3](https://www.rfc-editor.org/rfc/rfc7518.html#section-6.2.1.2) require full-width coordinates. Import rejects short or extended representations before the native point check and before the existing [RFC 7638 thumbprint computation](https://www.rfc-editor.org/rfc/rfc7638.html#section-7). It does not silently normalize an inadmissible representation into a key identifier. A full-width point must still lie on the selected curve.

Signed issuer discovery validates the pinned leaf, certificate chain, certificate validity and constraints before applying the JOSE algorithm gate to the leaf's public key. Metadata claims, endpoint origin and lifetime remain separate requirements. Rejected discovery does not install metadata or a signer, and rejected rediscovery preserves previously authenticated state. This is an algorithm and representation admission contract; it does not establish issuance authority or production qualification. The COSE algorithm registry is outside this selection.

[jose-p256-admission.json](../reference/vectors/jose-p256-admission.json) contains fresh synthetic public inputs, exact compact signing bytes, signatures, public keys and certificate chains. Its generator uses native cryptography and a separate DER writer. Private keys are not retained. The corpus includes native-valid wrong-curve signatures, a same-width secp256k1 signature, signature width and encoding negatives, detached inputs, and alternate encodings of the same P-256 point. [jose-p256-admission.test.mjs](../reference/jose-p256-admission.test.mjs) checks the raw signatures independently and exercises signing, verification, JWK import, thumbprints and the wallet discovery entry point with positive and negative controls.
