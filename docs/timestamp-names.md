# Timestamp optional fields and signer names

The optional `TSTInfo.tsa` GeneralName is a signed name hint. [RFC 3161 section 2.4.2](https://www.rfc-editor.org/rfc/rfc3161.html#section-2.4.2), as updated by [RFC 5816 section 2.2.2](https://www.rfc-editor.org/rfc/rfc5816.html#section-2.2.2), requires it to correspond to a subject name in the certificate used to verify the token. The ESS certificate identifier still selects the signer certificate independently.

Optional TSTInfo fields retain their ASN.1 SEQUENCE order: accuracy, ordering, nonce, tsa, then extensions. A present field cannot appear before an earlier-ranked field; omitted fields do not occupy a position. Duplicate fields remain rejected independently. Unselected extensions remain unsupported. Fully signed out-of-order encodings are rejected even when their fields and cryptographic commitments are otherwise unchanged.

The `CERTCONCORD-PQ` and `EXTERNAL-RFC3161` modes of [timestamp.mjs](../reference/timestamp.mjs) enforce this binding after CMS signature and ESS verification. The selected name form is `directoryName`: its exact DER Name must equal the signer certificate's subject or a `directoryName` in that same certificate's subjectAltName extension. The issuer name, another certificate's names, and a common-name string extracted from a different encoding cannot satisfy the check. A missing optional field remains supported.

This is an exact-DER subset. It does not implement the complete distinguished-name equivalence rules of RFC 5280 section 7.1; differently encoded equivalent names are not accepted by this subset. Other GeneralName forms produce `TSA_NAME_UNSUPPORTED` with an `UNSUPPORTED` outcome, including a DNS name that matches a certificate SAN. Empty or multiple names, malformed directoryName wrappers, invalid RDN structure and duplicate `tsa` fields are rejected. Malformed SAN GeneralName choice tags are rejected even when another name matches. A supported name that does not match produces `TSA_NAME_BINDING`.

Name matching supplies no issuer trust, TSA role, policy admission, status or clock assurance. It cannot replace the ESS binding, content digest, signature, certificate validity or critical exclusive timeStamping EKU checks. The separate CAdES/PAdES inspector retains its own selected name and trust contract; this helper does not broaden those profiles.

[timestamp-name-contract.json](../reference/vectors/timestamp-name-contract.json) retains synthetic signed tokens, exact TSTInfo and signed-attribute bytes, public certificates and keys, hashes and expected results. [timestamp-name.test.mjs](../reference/timestamp-name.test.mjs) replays both helper modes and independently checks signatures and content digests, including signed optional-field permutations, signed mismatches, malformed names, unsupported choices, ESS substitution, content/signature tampering and wrong issuer/EKU controls. [The generator](../tools/create-timestamp-name-vectors.mjs) creates fresh synthetic keys in memory and writes no private keys. These vectors establish the selected helper contract, not operational TSA qualification or a complete independent implementation.
