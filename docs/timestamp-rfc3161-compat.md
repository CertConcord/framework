# Selected PQ timestamp certificate delivery and HTTP reply

The `CERTCONCORD-PQ` timestamp helper uses RFC 3161's `certReq` request bit to select the CMS `SignedData.certificates` field. A true request includes the TSA certificate identified by the signed ESS certificate reference. A request with the field absent omits the entire certificates field. This follows [RFC 3161 section 2.4.1](https://www.rfc-editor.org/rfc/rfc3161.html#section-2.4.1) and the optional field in [RFC 5652 section 5.1](https://www.rfc-editor.org/rfc/rfc5652.html#section-5.1). The request builder's default remains true; selecting false emits no Boolean field in the DER request.

The selected verifier can use an explicitly supplied TSA certificate when the token has no embedded certificate. It still checks the signer identifier, signed ESS certificate hash, content digest, cryptographic signature, TSA profile and issuer signature under the supplied trust inputs. An external certificate is never treated as embedded. A client that knows its own `certReq` value also rejects the opposite response shape. Generic CMS verification continues to require an embedded certificate unless the caller explicitly enables the external-certificate path and supplies the expected certificate.

The HTTPS helper accepts `application/timestamp-reply` when the media type's type and subtype differ only in ASCII case, including a response with parameters. It rejects a different type before consuming the body. [RFC 3161 section 3.4](https://www.rfc-editor.org/rfc/rfc3161.html#section-3.4) names the timestamp reply MIME object, and [RFC 9110 section 8.3.1](https://www.rfc-editor.org/rfc/rfc9110.html#section-8.3.1) makes type and subtype case-insensitive.

The [fixed synthetic corpus](../reference/vectors/timestamp-certreq-contract.json) retains exact true and absent request/response/token bytes, the public TSA certificate and root key, and a token with a changed signature byte. [The vector test](../reference/timestamp-certreq-vectors.test.mjs) checks original hashes, CMS field presence, an independent Node cryptographic signature check, signed content digest, trust inputs and negative controls. [The generator](../tools/create-timestamp-certreq-vectors.mjs) writes no private keys. The HTTP regression uses identical signed response bytes for lowercase and mixed-case headers.

This helper contract concerns the selected `CERTCONCORD-PQ` path in `timestamp.mjs`. The separate [standalone timestamp application](timestamp-application.md) has its own P-256, authority, clock and durable operation contract. The `EXTERNAL-RFC3161` helper mode retains its separate verifier restrictions. These synthetic checks do not establish operational TSA time accuracy, assessed custody, an external service deployment or a second complete independent implementation.
