# Timestamp time and interval contract

The selected `timestamp.mjs` helpers authenticate RFC 3161 CMS tokens for document and preservation evidence. Their Number-valued time interface is separate from the application service's integer-microsecond verifier. Neither interface establishes clock calibration, trustworthy revocation collection or production eligibility.

[RFC 3161 section 2.4.2](https://www.rfc-editor.org/rfc/rfc3161.html#section-2.4.2) requires UTC GeneralizedTime with seconds and canonical fractional seconds: trailing zeroes are omitted, and an all-zero fraction is omitted entirely. The helpers reject invalid calendar dates, normalized midnight/day overflow, empty fractions and trailing fractional zeroes as `TST_TIME`. They support whole seconds and fractions of one to three digits. A canonical finer fraction is `UNSUPPORTED` with `TST_TIME_PRECISION_UNSUPPORTED`; it is never truncated to milliseconds. This is a selected implementation limit, not a restriction imposed by RFC 3161.

Accuracy is separate from generation-time precision. Its signed seconds, milliseconds and microseconds components remain supported, including an empty present Accuracy SEQUENCE, whose value is zero. An absent Accuracy remains unknown. The helpers accumulate the present components and both interval endpoints in integer microseconds before converting to Number seconds. `poeLowerBound` rounds outward toward negative infinity and `poeUpperBound` toward positive infinity; already exactly representable endpoints are unchanged. Even zero accuracy can enclose a non-binary fraction with two adjacent Number values. Consumers must use these bounds instead of reconstructing them from the displayed `genTime` and `accuracy`.

A configured finite `revokedAt` must be a Number. Both helper signature profiles require explicit accuracy and `poeUpperBound < revokedAt`. Equality and an interval crossing the cutoff are `INVALID` with `TSA_TIME_OR_REVOCATION`. Missing accuracy with an otherwise valid finite cutoff is `INDETERMINATE` with `TSA_ACCURACY_REQUIRED`; it does not mask independently established bad signature, request binding, nominal time, certificate or trust failures. The default `Infinity` does not infer zero accuracy or establish a good revocation status. Cutoffs are evaluated as their actual binary64 values, without claiming arbitrary decimal precision.

Nominal future-time checks remain separate. DOCUMENT still requires the complete interval within the TSA certificate period and no later than knowledge time, plus admissible status and authority decisions. DER ERS and XMLERS retain their original-proof, renewal, final-protection and hash-lifetime gates. The Framework [lifetime adapter](../reference/preservation-lifetimes.mjs) applies the selected component's chain and deadline rules to authenticated outward bounds, including `previous.poeUpperBound <= next.poeLowerBound`. The pinned component snapshot and its source hashes remain unchanged. Conservative rounding may reject two mathematically adjacent intervals when their common endpoint is not exactly representable; the helpers do not infer ordering to recover such acceptance.

The organization publication and selected AdES consumers also use the parsed lower bound for interval order and lower-end authority checks. This arithmetic contract does not add a container profile or confer an AdES level. The separate [TSA name contract](timestamp-names.md) continues to bind the actual signer.

The [signed raw corpus](../reference/vectors/timestamp-time-contract.json) covers canonical supported and unselected precision, malformed fractions and calendars, finite cutoffs, unknown accuracy, trust and signature controls. Run `node --test reference/timestamp-time.test.mjs reference/timestamp-time-integration.test.mjs` for raw replay and complete document/DER ERS/XMLERS interval decisions. All keys, clocks and status policies in these tests are synthetic.
