# Direct OCSP structure admission

The optional direct OCSP adapter accepts the bounded successful-response shape in [RFC 6960 §4.2.1](https://www.rfc-editor.org/rfc/rfc6960.html#section-4.2.1). The outer `OCSPResponseStatus` is a single zero octet. Its explicit `responseBytes` contains one `ResponseBytes` SEQUENCE with exactly a basic-response OBJECT IDENTIFIER and an OCTET STRING. The OCTET STRING contains a `BasicOCSPResponse` SEQUENCE with `ResponseData`, `AlgorithmIdentifier`, and a signature BIT STRING. A fourth member is admitted only as `[0] EXPLICIT` certificate SEQUENCE; each certificate requires the three-field [RFC 5280 §4.1](https://www.rfc-editor.org/rfc/rfc5280.html#section-4.1) envelope. Extra members and other fourth-member tags are invalid. Embedded certificates are not used to establish responder authority.

The signed `ResponseData.responderID` byKey `[2]` wrapper contains exactly one KeyHash OCTET STRING. Its `responses` field is a SEQUENCE OF SingleResponse; a SET container or context-specific response item is invalid. Each admitted SingleResponse is a SEQUENCE with `[0] EXPLICIT` nextUpdate containing one GeneralizedTime. The `responseExtensions` field is one `[1] EXPLICIT` wrapper containing one Extensions SEQUENCE. An additional NULL inside either wrapper is invalid, even when the signed bytes verify mathematically. The adapter applies [RFC 9654 §2.1](https://www.rfc-editor.org/rfc/rfc9654.html#section-2.1) to both request and response nonce extensions: the Extension `extnValue` is an OCTET STRING that encloses a DER OCTET STRING. This reference profile retains its existing 16–32 octet nonce length bound within the RFC's 1–128 octet type. Matching value bytes with either wrong tag do not establish a valid nonce binding.

The [structural admission tests](../reference/ocsp-structural-admission.test.mjs) preserve the original successful-status and signature-tag regression corpus. The [DER boundary tests](../reference/ocsp-der-boundaries.test.mjs) pin synthetic issuer-signed positive and negative responses, check each response signature independently, retain an accepted explicit certificate member, and reject malformed ResponseBytes, BasicOCSPResponse, responderID, responses, nextUpdate and responseExtensions fields, and nonce encodings. Signature verification and structural admission are separate from issuer-path authorization, status-history trust, and complete CAdES or PAdES document acceptance.
