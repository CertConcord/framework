# ACME CSR DNS identifier admission

[RFC 8555 section 7.4](https://www.rfc-editor.org/rfc/rfc8555.html#section-7.4) binds a finalization CSR to the order's identifiers. A `dNSName` in `subjectAltName` is an IA5String under [RFC 5280 section 4.2.1.6](https://www.rfc-editor.org/rfc/rfc5280.html#section-4.2.1.6); its octets must be ASCII before conversion to a JavaScript string.

For the reference DNS enrollment profile, every CSR GeneralName must have the primitive `dNSName` tag and contain only octets below `0x80`. The requested and ordered identifier lists must have equal lengths and compare exactly, element by element, after sorting. A comma-separated string is not an identifier-list representation: a single name containing a comma cannot stand for two order identifiers. Duplicate, missing, additional, non-DNS, or different requested names fail this comparison. Existing order-name admission, case comparison and A-label handling remain unchanged.

These checks run after CSR signature and account-key validation, and before changing the order to `processing`, requesting RA approval, or invoking issuance. Rejection raises `ACME_CSR_IDENTIFIERS`, leaves the order and its authorizations unchanged, and consumes the authenticated request's nonce. A ready order can subsequently accept a valid CSR using a fresh nonce. Device-attestation enrollment retains its separate no-SAN and attested-key requirements.

Passing identifier admission does not replace nonce and JWS authentication, account status and ownership, challenge readiness, account-key exclusion, or RA approval. Issuance still requires the returned certificate's public key and raw SAN bytes to match the CSR. RA denial or an invalid issuer result retains the existing `processing` state and never produces a valid certificate response.

[The frozen vectors](../reference/vectors/acme-dns-ia5.json) contain fresh synthetic, signed DER CSRs and matching synthetic certificates. They cover single and reordered DNS names, an IDNA A-label, high-bit octets, comma aliasing, and identifier-list mismatch controls. [The tests](../reference/acme-dns-ia5.test.mjs) verify raw signatures with Node's cryptographic primitives and exercise authenticated service requests, nonce replay, state preservation, RA denial, and issued key/SAN substitutions. The [generator](../tools/create-acme-dns-ia5-vectors.mjs) uses an independent DER writer and ephemeral synthetic keys; it does not serialize private keys. These fixtures establish the bounded reference-adapter contract, not real DNS ownership or production CA qualification.
